# 要件定義

## 1. 背景

外食・中食で食べたものを写真に撮っているが、カメラロールに埋もれて探せない。
その結果、以下のような場面で困っている。


| 場面        | 困っていること                      |
| --------- | ---------------------------- |
| 行きつけの洋食屋  | 毎回違うメニューを頼みたいが、どれを食べたか思い出せない |
| コンビニのスイーツ | 新発売を選びたいが、似たものを前に食べたか判断できない  |
| スターバックス   | カスタムして注文するが、前回のカスタム内容を再現できない |
| ケーキ屋の季節限定 | 去年も食べたのか、そのとき美味しかったのかが分からない  |


## 2. 目的

**いろんな味を楽しむこと。**

同じものばかりにならないように、食べたものを記録し、
「食べた／まだ食べていない」がすぐ分かる状態をつくる。

## 3. 解決したい課題

> 「これ、前に食べたっけ？ そのときどうだった？」が思い出せない

このアプリの本体は記録機能ではなく、**店の前・棚の前で3秒で引ける検索**である。

## 4. ターゲットユーザー

- 外食・中食が好きで、食べたものを写真に撮る習慣がある人
- 同じ店で違うメニューを試したい、新商品を選びたいという志向がある人
- 写真は撮るが整理はしない人



## 5. 機能要件



### 5.1 MVP（初回リリースに含む）


| #   | 機能      | 内容                                |
| --- | ------- | --------------------------------- |
| 1   | ログイン    | Google アカウントでのログイン（Supabase Auth） |
| 2   | 記録の登録   | 写真・食べた日・店・商品・評価（★1-5）・感想・カスタム内容   |
| 3   | 記録の一覧   | 写真グリッドで新しい順に表示                    |
| 4   | 検索      | 商品名・店名・分類で「前に食べたか」を検索             |
| 5   | 店ごとの制覇率 | 店のメニューに対する「食べた／未食」の可視化            |
| 6   | カレンダー表示 | 月表示。食べた日に写真サムネイルを表示               |
| 7   | いいね     | 他ユーザーの記録にいいねを付ける                  |
| 8   | マスタ管理   | 分類・業態の追加（管理者のみ）                   |




### 5.2 将来対応（MVPに含まない）

- 記録ごとの公開範囲設定
- 前回のカスタムをコピーして登録
- 統計（よく食べるもの、評価の高い順）
- 季節限定商品の再登場検知（去年の同時期に食べたものを提示）
- フォロー機能



### 5.3 主要な処理フロー

#### 初回ログイン時のユーザー登録

Supabase Auth でログインしても、MySQL の `users` には自動では作成されない。
Next.js が明示的に登録APIを呼ぶ方式とする。

1. Google でログイン（Supabase Auth）
2. Next.js の middleware が `users` の登録状況を確認
3. 未登録なら `/onboarding`（ニックネーム入力画面）へリダイレクト
4. ニックネームを入力して送信
5. `POST /api/users` で Spring Boot が `users` を作成（`id` は JWT の `sub`）
6. 以降は通常の画面へ

middleware が全ルートを通るため、URL を直接指定されても登録画面へ誘導される。
加えて Spring Boot 側でも、`users` が存在しない状態のリクエストは 403 を返す。

#### 画像アップロードとデータの整合性

画像を Supabase Storage にアップロードした後で `records` の登録に失敗すると、
どこからも参照されない「孤児ファイル」が残る。2段構えで対処する。

| 対策 | 内容 |
|---|---|
| 即時の補償処理 | `records` の登録に失敗した場合、アップロード済みの画像を削除する |
| 日次のバッチ | 補償処理自体が失敗した場合に備え、参照されていない画像を定期的に削除する |

バッチの削除条件は「`records.photo_url` から参照されていない」かつ
「**作成から24時間以上経過している**」とする。猶予を設けないと、アップロード直後で
まだ `records` の登録が終わっていないファイルを削除してしまうため。

記録を削除したときは、`records` の物理削除と同時に Storage の画像も削除する。

## 6. 非機能要件


| 項目    | 要件                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 画像    | アップロード時にブラウザ側でリサイズ・圧縮する（Supabase Storage の無料枠が 1GB のため）                    |
| 表示    | レスポンシブ対応。スマホでの記録、PCでの閲覧の両方を想定                                              |
| 認証    | Supabase Auth が発行する JWT を Spring Security で検証する                            |
| 認可    | 他ユーザーの記録は閲覧のみ可。編集・削除は本人のみ                                                  |
| Storage のアクセス制御 | 閲覧は全ユーザーに許可（全記録を公開扱いとするため）。アップロードと削除は本人のみに制限する |
| 外部API の利用制御 | Google Places API は従量課金のため、APIキーに参照元制限とAPI制限をかけ、Field Mask で取得項目を絞り、Autocomplete はセッショントークンを使用する。予算アラートを設定する |
| 文字コード | 絵文字を保存するため MySQL は utf8mb4 を使用                                             |
| 稼働    | Supabase の無料プランは1週間アクセスがないとプロジェクトが停止するため、GitHub Actions の cron で定期的にアクセスする |




## 7. スコープ外（あえてやらないこと）


| 項目          | 理由                                                  |
| ----------- | --------------------------------------------------- |
| 記録ごとの公開範囲設定 | MVP では全記録を公開扱いとする。カラム追加で後から対応可能なため                  |
| 店舗単位の管理     | 店は「店名 + エリア」で一意とする。コンビニなど同一チェーンの商品を横断して検索できることを優先した |
| 商品の販売期間管理   | 入力の手間に見合わないため、`is_seasonal` フラグのみとする                |
| 献立の提案機能     | 提案の質を担保するのが難しく、スコープが膨らむため                           |
| フォロー機能      | タイムラインは全公開記録の新着順で成立するため                             |




## 8. 技術構成

```
Next.js 16 (App Router)
    ↓ REST API + Bearer JWT
Spring Boot 3（3層 + MyBatis + Spring Security）
    ↓
MySQL 8.4 LTS
    +
Supabase Auth（Google OAuth）/ Supabase Storage（写真）
```


| 領域      | 技術                                                                         |
| ------- | -------------------------------------------------------------------------- |
| フロントエンド | Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS / shadcn/ui |
| バックエンド  | Java 21 / Spring Boot 3 / MyBatis / Spring Security                        |
| データベース  | MySQL 8.4 LTS（Docker Compose）                                                  |
| 認証      | Supabase Auth（Google OAuth）                                                |
| ファイル保存  | Supabase Storage                                                           |
| 外部API   | Google Places API（店名の入力補助）                                                 |
| CI/CD   | GitHub Actions                                                             |
| デプロイ先 | Vercel（Next.js）/ Railway（Spring Boot + MySQL） |


技術選定の理由は別途 `技術選定.md` に記載する。
